# AIDesk 需求规格说明书

项目名称：AIDesk 基于 ESP32 的办公陪伴机器人及多端控制台

编制日期：2026-10-23。个人信息以选题申报表、开题报告和答辩 PPT 中的填写内容为准。

## 1 文档目的与依据

本说明书用于项目验收与后续迭代，依据 memory_bank 九份项目文档、当前工作区代码、migrations 与测试结果整理。项目记忆的早期段落保留了当时状态，本文以较晚任务记录和实际代码交叉核对，不把开题规划自动视为完成事实。本包记录的是 2026-10-23 工作区快照，包含尚未提交的会议纪要代码。

## 2 产品定位与用户

AIDesk 是面向桌面机器人使用者与开发者的中文控制台。访客可以注册和登录；注册用户维护自己的模型、角色、会话和设备；设备终端以独立设备密钥访问指定接口。各端只有指向同一个服务实例时才共享该实例的数据，本机独立 SQLite 与云端数据库不会自动相互同步。

## 3 典型使用流程

首次使用先注册账户，添加获准模型服务并填写 API key，再建立关联模型的角色。用户选择角色开始流式对话，也可绑定设备，将一次性设备码与服务器地址填入机器人的配网页。设备获取指令后执行并回报。语音使用前需配置语音凭据和角色。会议功能从创建会议、导入文本或采集音频开始，校对发言后生成纪要。Agent 通知由独立上报凭据接入，远程批准必须有明确的人类决定。

## 4 功能需求与验收

### FR01 用户与权限

功能：注册、登录、退出、会话保持；账号间数据隔离。

验收：未登录返回 401；跨账号资源返回 404；密码不明文入库。

当前状态：实现并有本地测试。

### FR02 模型管理

功能：模型参数维护、密钥加密与掩码、连接测试。

验收：读取接口不泄漏明文密钥；仅访问获准 HTTPS 域名。

当前状态：实现并有本地测试，真实供应商本次未调用。

### FR03 角色设定

功能：系统提示词、任务、关联模型配置。

验收：禁止关联其他用户的模型；角色影响后续会话上下文。

当前状态：实现并有本地测试。

### FR04 流式会话

功能：SSE 回复、持久暂停续写、撤销与重新生成。

验收：暂停后保留片段；继续写入同一回复；旧 token 不覆盖新状态。

当前状态：实现并有本地测试。

### FR05 设备管理

功能：绑定、短码鉴权、状态上报、指令下发与回执。

验收：密钥一次性显示；解绑后失效；轮询后状态可追踪。

当前状态：实现，2026-10-14 历史真机记录支持。

### FR06 语音交互

功能：PCM 录音、ASR、模型生成、逐句 TTS、设备回放。

验收：出错有失败记录；BOOT 取消；连续对话与唤醒打断需真机复测。

当前状态：服务端与固件已有实现，本次无真机复测。

### FR07 会议纪要

功能：文本导入、音频分块转写、发言编辑、说话人命名、纪要生成。

验收：账号隔离；生成错误可见；不推测未知发言人姓名。

当前状态：当前工作区已有实现与测试，真实录音及模型链路待验收。

### FR08 Agent 动态

功能：上报事件、机器人短播报、手机通知、远程批准或拒绝。

验收：凭据哈希保存；决定一次生效；超时不自动放行。

当前状态：实现并有测试及历史命令验收记录，手机通知待复测。

### FR09 多端接入

功能：Web 响应式、Android WebView、Electron、原生微信小程序。

验收：各端指向同一服务时共享账户业务数据。

当前状态：源码齐备；本次只验证浏览器与 Node 启动包。

### FR10 MCP 工具接入

功能：后续服务端注册工具、鉴权、调用、审计。

验收：需另行设计白名单与权限后验收。

当前状态：规划项，未发现完整实现，不计已完成。

## 5 交互与异常状态

界面覆盖加载、空数据、错误、保存中、删除确认与键盘焦点。聊天回车发送、Shift+回车换行，中文输入法组合态不误发；用户上滑时停止自动跟随。生成运行中禁止冲突写入，暂停、失败、完成分别呈现对应操作。设备状态区分在线与最后在线时间，指令区分待执行、已下发、完成和失败。模型连接错误按 HTTP、网络、超时和协议类展示安全摘要。

## 6 数据与安全要求

密码采用 PBKDF2 加盐派生，会话令牌以哈希保存。Web 使用 HttpOnly Cookie，小程序使用受控 Bearer 会话通道。所有用户资源按 user_id 授权；设备和 Agent 使用独立凭据。模型及语音凭据使用服务端 AES-GCM 加密，前端只接收掩码。供应商地址限制 HTTPS、域名白名单、禁止私有字面地址和重定向，不宣称完全解决 DNS 重绑定。加密主密钥丢失会导致旧密文无法解密，必须单独保管。

## 7 非功能与约束

Web 设计覆盖手机、平板和桌面宽度。设备控制采用 HTTP 轮询，不承诺硬实时；延迟取决于轮询周期与网络。真实模型与语音服务需有效账号、开通资源和网络。容器当前依赖 SQLite 快照与种子，不具备持久数据库保障，发布前仍须使用仓库的一键部署脚本。本文不把历史单次延迟作为普遍性能保证。
