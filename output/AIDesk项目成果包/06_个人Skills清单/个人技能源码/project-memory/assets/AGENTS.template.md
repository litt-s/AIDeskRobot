# <项目名> 项目协作规则

> 将 <项目名> 和 <记忆目录> 替换为实际值。新项目默认记忆目录为 memory_bank；已有 memory-bank 时沿用。合并到已有规则时保留用户有效约束。

## 项目启动与变更确认

- 开始项目先询问项目目标、用户、需求、预期效果和约束，商讨技术栈。
- 将需求、技术选型、验收标准和编号任务拆分提交用户明确确认，通过后建立记忆文档并实施。
- 已有项目先读取记忆，确认本次目标与变化，不重复询问已经确认的信息。
- 范围、验收或技术栈有实质变化时，先更新方案并取得明确确认，再实施。

## 项目记忆入口

<记忆目录>/ 是权威项目记忆，内容必须与实际项目保持同步。

开始任务前阅读：

- <记忆目录>/PRD.md：产品需求与验收。
- <记忆目录>/TECH_STACK.md：技术方案与开发约束。
- <记忆目录>/DESIGN.md：效果、界面和交互。
- <记忆目录>/DATA_MODEL.md：数据与接口契约。
- <记忆目录>/ARCHITECTURE.md：目录职责、边界与数据流。
- <记忆目录>/TASKS.md：编号任务、范围、依赖和状态。
- <记忆目录>/PROGRESS.md：当前进度、证据和阻塞。
- <记忆目录>/LEARNINGS.md：相关实证问题与预防方法。
- 部署或交付任务另读 <记忆目录>/DEPLOY.md。

## 任务执行

- 一次只执行一个已批准、依赖满足的编号任务。
- 默认单任务模式；用户明确授权连续执行时，完成当前项并同步文档后再顺序执行下一项。
- 不实现清单之外的功能，不顺手实现后续任务。
- 发现范围外问题记录为待处理候选项。
- 规格不合理时先修正文档；改变批准边界时重新确认。
- 效果对齐 DESIGN，字段和接口对齐 DATA_MODEL，模块边界对齐 ARCHITECTURE。

## 文档同步与完成标准

- 每次有意义的代码、依赖、配置、界面、接口、数据、部署或验收变更结束前，自动同步相关文档和 PROGRESS。
- 产品范围更新 PRD；技术及环境更新 TECH_STACK；视觉与交互更新 DESIGN；数据与契约更新 DATA_MODEL；目录与链路更新 ARCHITECTURE；任务状态更新 TASKS；运行与交付更新 DEPLOY；已确认根因与修复更新 LEARNINGS。
- 验收通过、相关文档同步后，才能把任务标为已完成；未验证项必须明确列出。
- TASKS 与 PROGRESS 的状态一致；当前进度摘要保持最新，历史工作记录按日期和任务编号保留。
- 报告任务编号、实现效果、修改文件、实际验证结果和剩余问题。
- 完善文档时全文阅读目标文档，补齐 TODO，也修正与批准需求或实际证据冲突的非 TODO 内容，保留有效通用规则。

## 项目资源与配置

- 不擅自删除 design/、项目记忆、用户文件或有效历史记录。
- 不把真实密码、token 或私钥写入源码、记忆文档、前端或版本库；敏感本地配置加入忽略规则，模板仅保留变量名和说明。
- 数据访问与鉴权遵循已批准架构，由可信边界执行授权和敏感操作；接口调用集中在适合技术栈的封装层。
- 遵守本项目实际通信与工具约束。仅在已明确采用纯文本代理时禁止图片、截图和可能注入非文本的浏览器工具。
