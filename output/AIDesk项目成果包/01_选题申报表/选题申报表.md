## 1 选题名称与类型

选题名称：基于 ESP32 的办公陪伴机器人及多端控制台的设计与实现。

选题类型：应用软件与嵌入式系统综合实践。课题来源：项目实践（学校认定类别待填写）。

## 2 选题背景

桌面机器人可以承载对话、表情和动作，但模型配置、语音凭据、设备状态与会话历史往往分散在不同入口。普通用户需要修改固件或重复配置客户端，开发者则需要同时处理设备鉴权、网络异常和跨端数据一致性。AIDesk 以中文 Web 控制台作为统一入口，把 ESP32 机器人作为受控终端，让用户在浏览器中完成模型、角色和设备配置。

## 3 研究与开发目标

实现统一账户下的模型管理、角色配置、流式聊天、设备绑定、状态上报、远程指令、语音对话和多端访问。利用服务端加密与租户授权控制模型凭据，建立可追踪的指令回执和生成状态。会议纪要在当前代码上继续完成真实音频验收；MCP 作为后续扩展，不作为现阶段已完成成果。

## 4 核心功能

1. 用户注册登录、会话鉴权和数据隔离。
2. OpenAI 兼容模型管理、密钥掩码和连接诊断。
3. 角色系统提示词、关联模型与会话历史。
4. SSE 流式回复、持久暂停续写、撤销及重新生成。
5. ESP32 绑定、状态上报、轮询指令和结果回报。
6. 火山 ASR、模型回复、TTS 分帧下发的语音链路。
7. 会议文本导入、发言整理和纪要生成入口。
8. Agent 事件通知、远程批准或拒绝与多端接入。

## 5 技术路线

React 19、TypeScript、Vite 构建响应式界面；Hono 统一业务 API。Cloudflare Worker 使用 D1，Node 入口以 node:sqlite 适配同一数据库接口并可部署 CloudBase 云托管。Android 采用 Java WebView 壳，PC 采用 Electron，小程序使用 WXML、WXSS、JavaScript。ESP32 固件通过 robot_cloud 组件接入设备通道，云端完成模型与语音服务编排。

## 6 特点与难点

数据库保存流式生成的状态、片段与 token，降低页面刷新导致的上下文丢失风险；设备通道以一次性短码和回执闭合控制链路；双运行时适配减少业务重复。重点难点是弱网流恢复、低带宽设备音频缓冲，以及远程批准在超时和并发下保持安全默认值。
