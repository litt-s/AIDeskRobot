## 结构与权限

业务数据位于独立 `aidesk` schema。服务端通过 HTTPS 调用 `public.aidesk_query(jsonb)`，沿用 D1 风格的 prepare/bind/first/all/run/batch 和既有账户授权。一个 batch 是一个数据库事务；失败整批回滚，写请求不自动重试。函数显式校验 `auth.role()=service_role`，使用 SECURITY INVOKER；anon/authenticated 无业务 schema 权限。CloudBase 的 API Key 仅注入服务端，绝不进入前端、源码或镜像。

整数使用 BIGINT，保留原 rowid 顺序及原字符串时间格式。原密码哈希、设备码哈希、凭据密文不变；必须保留原 ENCRYPTION_KEY。新增数据模型时，为 SQLite 和 PG 分别添加迁移，不能仅修改根 migrations/ 后部署。
